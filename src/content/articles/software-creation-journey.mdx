下面按时间顺序，记录我依次开发的五款软件——它们各自从上一款的经验里长出来，又指向下一款要解决的问题。

## 创客计划

### 动机

第一个开发的项目是我们的创客计划——一个复习卡片的编写和复习软件。之所以想做这个，是因为我觉得当前市面上比较流行的复习软件要么噪音很多、界面不干净，要么功能实现得很糟。所谓「不干净」，指的是界面 UI 非常凌乱，复习功能不是一等公民，而是被隐藏在二级入口。复习时常常要求你先选择要复习的 deck，而不是直接允许你开启一天的复习，这会产生很多阻力和噪音。编辑卡片的编辑器也做得很拧巴，功能不够强大和完善。

### 核心设计

我们理想中的卡片编辑器应该支持：

- QA 卡片的闭合挖空
- 图片支招挖空
- 更强大的表格类挖空（暂不强调）

基础的遮罩文本挖空是将不同的支招块合并为同一个复习内容，合并成同一个复习的遮罩块，然后进行回忆。每一次回忆时将其他支招块隐藏。简单来说，就是「hide one, test all」和「merge different clozes」这种能力，在很多编辑器中都没有实现。因此，我想把它做成一个极简、易用的小软件。

第二个需求是拥有非常灵活的批量导入 flashcard 的能力。做好单一输入后，我希望软件能够一次性导入大量 flashcard，这样我们就可以像做笔记一样编写复习卡片，并将它们合适地归类到我们的内容中。

## Aletheia

### 动机

我做的第二个项目是 [Aletheia](/projects/aletheia)，意思是「照亮」。它的功能主要是在英文阅读时进行查词。所谓「照亮」，就是像灯一样点亮阅读时的困惑和迷茫。

### 核心设计

核心点有两个：

1. 查词的交互没有侵略性，做得相对简洁，不会剧烈改变你的阅读样式，搞的五六种颜色标注，最后都没法读，注意力全被标注吸引走了。并引入 AI 技术，让 AI 结合语境（context）来查询单词在语境中的含义，而不是调用传统词典。传统词典可能给出 5 到 10 种含义，用户需要自行匹配，这对阅读过程是巨大的阻力。我们在这里调用 LLM，将查词所在的上下文发送给 AI Agent，让其返回相关的语境含义。

2. 查词后如果不复习效率很低，所以我们又做了一个简单的复习软件，复习交互直接引用了第一个项目中使用的左滑、右滑、上滑、下滑等动画，实现了复用。

## Networks

### 动机

我做的第三个项目的名称叫 [Networks](/projects/network)，它是一款笔记工具。简单来说，我希望把它做成一个 Heptabase，但每一张卡片的能力都被强化，既可以作为文件夹，也可以作为文档。

### 核心设计

它会有 5、6 种不同类型的卡片，包括 Excalidraw、Whiteboard、普通的卡片等。但我发现自己的开发过分发散，直接做崩溃了，因为我的精力与时间只能支持做好一个单一卡片 + folder 与 card 机制，而它现在的难度要大的多。

## Robert

### 与前一项目的关系

我做的第四个项目是一个笔记软件，它一开始的名称叫 [Robert](/projects/robert)，是因为我觉得这很像一个管家的名字，我想让它做我们的 personal context manager。它的功能与定位是：首先这个笔记软件的结构沿用 Networks 中一条可以有多个 parent card，每一条笔记既是一个 folder 也是一个 document 的设计。所以它既可以用来存储笔记内容，也可以用来导航探索找到笔记。

### 核心设计

但由于多个 parent card 过分灵活，如果由我们用户手动来匹配这些 parent card，就相当原来我们只需要给一条笔记找一个 folder 去存储管理，现在我们需要找到多个 folder，那就会带来非常大的阻力和使用疲惫，因此我们引入了 robert agent，我们尝试创建一种异步 agent 确认机制来跟用户达成哪些内容需要保留和不保留的共识。设计的思路是：每天晚上 agent 会获取一部分用户给定的 context，然后结合它已知的信息，进行结构探索，比如用户原来就有一些编程笔记的 card，然后今天它写了 5 条编程心得卡片，agent 读完今天写的 5 条笔记后，就会想到以前创建的「编程笔记」然后发送一条确认给用户：是否要将这 5 张卡片连接为「编程卡片」的子卡片。

## Trace

### 动机

我做的第五个软件是 [Trace](/projects/deeptalk)，它的功能与定位是一个 agent 阅读聊天器，但又结合了学习能力。

### 核心设计

1. 它是一个 ai chat 软件，但支持子 thread 能力，这允许你在聊天中开启新的分支，保留清晰的 context，easily 深入任何你好奇的领域；

2. 它是一个 agent 辅助的 flashcard 软件，当你阅读了好奇的内容，你会将你想要学习与记忆的内容进行 highlight，然后 agent 会为你的 highlight 生成 flashcards；

3. 因为我想阅读英文内容，直接学习原文，所以我又给它引入了 Aletheia 中做过的生词卡片能力，它能结合 context 查询生词的语境义，并且允许收藏生成单词卡片复习。

In time order: five pieces of software. Each grew out of the last, and each pointed at the next problem.

## Maker Plan

### Motive

The first project was Maker Plan — an app for writing and reviewing flashcards. Popular review apps were either noisy and messy, or badly built. “Messy” meant a cluttered UI, with review buried behind a second-level door. You often had to pick a deck before starting the day’s review. The editor was awkward, too: not powerful, not finished.

### Design

The editor I wanted:

- Cloze on Q&A cards
- Image-hint clozes
- Stronger table clozes (not the first priority)

Masked-text cloze merges different hint blocks into one review item, then hides the others on each recall. In short: “hide one, test all” and “merge different clozes” — missing from many editors. I wanted a small, quiet app that did this well.

The second need was flexible bulk import. Once a single card worked, I wanted to import a lot at once, write cards the way I write notes, and file them into the content.

## Aletheia

### Motive

The second project is [Aletheia](/projects/aletheia), “to bring to light.” Lookup while reading English. A lamp on the confusion of reading.

### Design

Two cores:

1. Lookup should not invade. Quiet, no riot of highlight colors that steal attention from the text. And AI in context: not a traditional dictionary with five to ten senses you have to match yourself — a real tax on reading. We send the surrounding context to an LLM agent and get the sense that fits.

2. Lookup without review is weak, so we built a small review module, reusing the swipe animations (left, right, up, down) from the first project.

## Networks

### Motive

The third project is [Networks](/projects/network), a notes tool. I wanted a Heptabase where every card was stronger: folder and document at once.

### Design

Five or six card types were planned: Excalidraw, Whiteboard, ordinary cards, and more. The work spread too far and collapsed. I only had the capacity to do a single card-plus-folder mechanism well, and the real difficulty was much larger.

## Robert

### Relation to the last project

The fourth project is a notes app first named [Robert](/projects/robert) — a butler’s name. I wanted a personal context manager. The structure follows Networks: a note can have several parent cards; each note is both a folder and a document. You store in it, and you navigate with it.

### Design

Several parents is too flexible. Matching them by hand is like finding one folder, except now you need several — a lot of resistance. So we introduced a robert agent: an async confirmation loop. Each evening the agent takes some of your context, explores structure against what it knows. You already have a “programming notes” card; today you wrote five notes on programming; the agent asks whether those five should become children of “programming notes.”

## Trace

### Motive

The fifth piece of software is [Trace](/projects/deeptalk) — an agent reading-chat with a learning loop. (The project file lives under Trace.)

### Design

1. An AI chat that can open sub-threads, keep context clean, and go deeper wherever you are curious;

2. Agent-assisted flashcards: highlight what you want to remember, and the agent turns the highlight into cards;

3. Because I want to read English in the original, it also inherits Aletheia’s vocabulary cards: in-context sense, save, review.
